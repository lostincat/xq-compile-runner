# Release acceptance checklist

All desktop checks below are **NOT RUN for this candidate**. Earlier private prototype results cannot qualify a changed public candidate. Keep SAC enabled throughout.

After reviewing source and obtaining a trusted signature:

1. Verify signature chain, publisher, timestamp, released artifact hash and SAC execution permission.
2. Manually create the disposable fixed test document; confirm exact XQ process path and one editor.
3. Submit a harmless non-order assignment; verify saved source and fresh zero-error summary.
4. Submit a deliberately unknown identifier; verify native error text and FAIL, not PASS.
5. Activate a different document; verify failure before any write.
6. Open a genuine modal XQ dialog; verify failure with no input actions. Resolve it manually.
7. Test desktop deadline and host watchdog in an isolated test environment; verify terminal failure without replay. Mock results alone do not qualify.
8. Check unsaved edits, locked desktop, stale log, clipboard contention and source changes.
9. Only then test the private Open WebUI integration, queue authentication/serialization, evidence validation and bounded repair. Do not test live orders.

Before signed release: verify CI build provenance, maintainer MFA, signing-service enrollment and release approval. The maintainer has authorized MIT source publication and an application; service acceptance and signed releases remain pending. Do not claim a signing provider has approved this project.
